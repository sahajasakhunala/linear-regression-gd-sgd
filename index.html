The Black-Box Dilemma
  • Standard libraries (like scikit-learn) solve linear regression in a single line.
  • This hides how gradients actually guide weights and bias toward the optimum.
  • Our Goal: Build Batch GD and SGD completely from scratch in NumPy to see the optimization process directly.
Drag to Move
Key Research Questions
  • Gradient Dynamics: How does full-batch updating differ from single-sample updating?
  • Trajectory: Does SGD oscillate heavily, and how fast does it reach convergence?
  • Generalization: Do both methods achieve equal predictive accuracy on unseen test data?

Mathematical Modeling
Hypothesis, Loss Function & Gradients
Analytical derivation for parameter optimization
Drag to Move
1. Hypothesis & MSE Loss

Linear Prediction Function:

ŷi = w · xi + b

Mean Squared Error (MSE):

MSE = (1 / n) Σ (yi - ŷi)2

MSE forms a convex bowl shape, guaranteeing a single global minimum with no local traps.

Drag to Move
2. Analytical Gradient Equations

Weight Gradient (dw):

dw = -(2 / n) Σ xi · (yi - ŷi)

Bias Gradient (db):

db = -(2 / n) Σ (yi - ŷi)

Parameters update along the negative gradient: w ← w - α·dw, b ← b - α·db

Why Features Remain Unscaled
  • Naturally Compact Range: Study hours spans [1.0, 8.0] with no multi-scale distortions.
  • Stable Convergence: With learning rate α = 0.01, gradients step smoothly without extreme zig-zagging.
  • Direct Interpretability:
    • Weight w = marks gained per study hour (~7.7 marks/hr).
    • Bias b = baseline score (~28.2 marks).
Drag to Move
Strict Preprocessing Rule
  • The Rule: If standardization is applied, mean and std must come only from the training set.
  • The Danger: Computing statistics over the entire dataset leaks future test distribution into training.
  • Implementation: Built a dedicated ZeroLeakageStandardScaler strictly respecting this isolation.
Algorithm 1
Batch Gradient Descent (GD)
Deterministic full-batch optimization across all training observations
Drag to Move
Algorithmic Workflow
  • Initialize: w₀ = 0.0, b₀ = 0.0, α = 0.01
  • Loop (1 to 1,000 iterations):
    1. Predict all 10 training samples: ŷ = w · X + b
    2. Compute exact mean gradient: dw and db
    3. Simultaneously update parameters:
    w ← w - α · dw   |   b ← b - α · db
    4. Record full-batch MSE loss.

Algorithm 2
Stochastic Gradient Descent (SGD)
Sample-by-sample online updates with per-epoch shuffling
Drag to Move
Algorithmic Workflow
  • Initialize: w₀ = 0.0, b₀ = 0.0, α = 0.01, seed = 42
  • Loop (1 to 100 epochs):
    1. Shuffle the 10 training samples randomly.
    2. For each sample (xi, yi) individually:
    w ← w - α · dwi   |   b ← b - α · dbi
    3. Record epoch-average MSE loss.

Practical Insights
Trajectory Comparison & Practical Trade-offs
Comparing optimization behavior and real-world scalability
Drag to Move
Optimization Path Contrast
  • Batch GD: Computes the true gradient over all samples. The loss drops smoothly and steadily in a direct monotonic line.
  • SGD: Updates after every single sample. Individual data noise causes the loss curve to fluctuate, but it makes fast early progress.
Drag to Move
When to Use Which?
  • Small Datasets: Batch GD is simple, stable, deterministic, and requires no data shuffling.
  • Large Datasets (Big Data / Deep Learning): Full-batch passes become too expensive. SGD or Mini-batch GD is essential for scale and memory efficiency.

Project Scope & Limitations
  • Sample Size (N = 15): Designed as a clear educational demonstration of gradient behavior rather than a real-world score predictor.
  • Small Test Set (n = 5): A 1-point difference on a single student shifts test MSE, so minor metric differences between GD and SGD are negligible.

Final Conclusion
Both Batch GD and SGD successfully optimized linear regression from scratch. Batch GD provided a smooth trajectory; SGD fluctuated but converged with 10× fewer sample evaluations. Both methods reached virtually identical test performance (Test MSE ~0.864).
